# Tasks: Instrument Tuner

**Input**: Design documents from `/specs/003-instrument-tuner/`

**Prerequisites**: plan.md, spec.md (clarified 2026-09-26), research.md (R1–R15), data-model.md (§1–§8), contracts/ (engine-c-abi-v2.md, tuner-audio-kotlin.md, tuner-domain.md, tuner-preferences.md, reference-sounds.md, microphone-permission.md, tuner-screen.md, design-system-additions.md), quickstart.md

**Tests**: Required. Constitution III (test-first, non-negotiable) and spec FR-028: every implementation task is preceded by the test that fails without it. Lanes, always with `--warning-mode all` from `app/`: `./gradlew engineHostTest` (Catch2, host), `./gradlew checkAndroidHost` (JVM), `./gradlew checkIos` (simulator), `./gradlew checkAndroidDevice` (device). Kotlin tests never link the engine; they use `FakeAudioEngine`, `FakeMicrophonePermission`, `FakeTunerPreferences` and a fake `ResourceReader`.

**Organization**: Setup adds the one dependency, the assets and the platform declarations. Foundational builds what every story needs: the domain, the C ABI revision 2 skeleton with the engine state machine and the Kotlin `TunerAudio` seam, the tokens and design-system components, the permission interface and its platform implementations, and the DI wiring. Each user story is then an independently testable increment: US1 (Auto Listen) adds the capture path and the meter, US2 the selectors, presets, By Ear cards and preferences, US3 the tone path and audition, US4 the loop toggle, US5 the denied state and interruptions, US6 the expanded layout, input and screen-reader proof.
