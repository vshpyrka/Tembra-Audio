# Quickstart: validating the Timeline Arranger (feature 009)

Run everything from `app/` through the `gradle-run` wrapper (constitution VIII). Contracts and
the data model hold the details; this guide only says what to run and what must be seen.

## 1. Prerequisites

- `app/README.md` toolchain (JDK, NDK, CMake, Xcode 27.1 beta for the iPhone on iOS 27);
  a Pixel 6 Pro and the iPhone 14 attached and unlocked; the iPhone 17 and iPad simulators
  booted; the Pixel 9 Pro Fold emulator for posture checks.
- `cd app/perf && uv sync` for the pipeline.
- FLAC and MP3 test fixtures under `specs/009-timeline-arranger/fixtures/` (generated by
  `fixtures/make_fixtures.py` from synthesised tones; committed).

## 2. Build, test lanes, gates

| Lane | Command | Must show |
|---|---|---|
| C++ | `./gradlew engineHostTest` | every new Catch2 file green (contracts/engine-c-abi-v6.md), `trace_poison` passes with the new RT sources |
| JVM | `./gradlew checkAndroidHost --warning-mode all` | domain, document, repository, session, ViewModel, layout and token tests green; `BaselineProfileCoverageTest` green after regeneration; `PerfSectionCatalogueTest`, `PerfAnchorsCatalogueTest` green; zero warnings |
| iOS simulator | `./gradlew checkIos -Ptembra.iosSimulator="iPhone 17"` | the same `commonTest` set plus `uiTest` and `iosTest` (engine round trip, session, pickers) |
| Android device | `./gradlew checkAndroidDevice` (or `gradlew-device <serial>`) | `uiTest`, `androidDeviceTest` (engine round trip, DataStore, files, picker host, focus) |
| Pipeline | `cd app/perf && uv run pytest` | config, catalogue, collectors and report tests with the fifth journey |
| Compose report | `./gradlew :shared:ui:assemble -PcomposeReports=true` | every new composable skippable or explained in the PR |

Install and run: `./gradlew :androidApp:installDebug` then
`adb shell am start -n audio.tembra.app/audio.tembra.android.MainActivity`; iOS per `CLAUDE.md`.

## 3. User Story 1 — play the demo (both platforms)

1. First launch → Timeline shows "Demo project": four tracks, five clips with waveforms, the
   readout `00:00.00 / 00:30.96`, play, metronome off, master 80 %.
2. Press play: sound within 100 ms, every clip audible together, the playhead sweeps the ruler
   and the lanes, the readout counts up; pause stops cleanly; play resumes; skip-to-start.
3. Tap the ruler at bar 5 while playing: continues from bar 5; drag the marker: silent, resumes
   on release.
4. Master volume drag: smooth, no crackle.
5. Lock the screen: playback continues; unlock, still playing.
6. Choose Tuner in the navigation while playing: the stop-and-leave dialog appears; "Keep
   playing" stays; repeat and "Stop and leave" pauses and opens Tuner; back to Timeline shows
   the paused position.
7. Play past the end: silence, the readout keeps counting.

Evidence: screen recording plus a recording of the output (headphone jack or USB interface) for
SC-002/SC-003 timing.

## 4. User Story 2 and 4 — tracks, import, edit, undo

1. Projects → New project → "Project 1" opens empty with the invitation.
2. "+ Track" twice: "Track 1", "Track 2", colours one and two.
3. Track 1 menu → Track settings: rename "Verse guitar", label Guitar; the header shows the chip.
4. Track 1 menu → Add audio… → pick a WAV: clip at the playhead, waveform fills in; Add audio as
   new track → pick three files (WAV, FLAC, MP3): three tracks appear in picker order; one undo
   removes all three.
5. Pick a 4-channel or 40-minute file: refused with the reason; pick an unsupported type: refused.
6. Gain from the header (expanded) or settings: readout and loudness follow; mute, solo,
   several solos, mute + solo silent.
7. Select a clip, place the playhead inside, split: two clips, identical sound across the cut;
   drag the second (long press on touch) later, then onto another track; delete it; undo and redo
   each step, including during playback.
8. Move up / Move down / Delete track with confirmation; undo restores.
9. Relaunch the app: the project reopens stopped at the start, identical.

## 5. User Story 3 — ruler, zoom, grid

1. Pinch on the lanes from the widest level (whole project ≥ 32 bars) to the closest (one beat
   spans the width): labels change bars → beats → sixteenths; minutes → seconds → hundredths;
   no overlapping labels at any level (capture ten levels).
2. Mouse: wheel scrolls, modifier + wheel zooms around the pointer, trackpad pinch zooms.
3. Playback follows the playhead by paging; a manual scroll stops following; skip-to-start
   restores it.
4. Grid 1/8: ruler taps land on eighths; Off: exact.

## 6. User Story 5 — metronome at the project tempo

1. Toggle on while playing: the click starts on the next beat, accent on bar lines.
2. Record ten minutes with a clip starting on bar 1 at 124 BPM: every click within 1 ms of its
   beat relative to the clip (offline analysis of the recording); repeat at 40 and 240 BPM, 4/4
   and 7/8 (SC-004).
3. Tap the tempo pill: the dial, steppers, slider and tap tempo; set 90: the ruler stretches,
   clips keep their bars, the click follows at the next tick, one undo step.
4. Tap the signature: 6/8: bars and ticks follow; positions in beats unchanged.
5. Long-press the toggle: the metronome settings sheet; change the sound and subdivision; open
   the Metronome destination (after the dialog): the same sound and subdivision there, its own
   tempo unchanged.

## 7. User Story 6 and 7 — track settings, library

1. Compact: settings open as a screen with the transport bar; the Effects section shows the
   placeholder sentence only; back returns at the same scroll and zoom. Expanded: inline under
   the header, one at a time, chevron collapses; resize across 840 dp (foldable or desktop
   window) keeps the edits.
2. Library: count, search (name and description), All/Recent, sort by name; the demo card's
   badge; Resume on the active card; Rename, Description, Key, Duplicate ("<name> copy"),
   Delete (open project → next most recent opens), Restore demo project.
3. Open `documents/projects/<id>/project.json` from the device: readable JSON, no path strings;
   copy a project folder from Android to iOS (or the reverse) and open it: identical arrangement
   and sound.
4. Force-quit two seconds after an edit twenty times: at most the last two seconds are lost.

## 8. Interruptions and routing (manual, both platforms)

| Case | Expected |
|---|---|
| Incoming call while playing | pauses at once; after the call stays paused; position kept |
| YouTube (or any app) starts playing in a separate window / split screen | our playback pauses when the other app takes the audio; never resumes by itself |
| Headphones unplugged | pauses; plugging in does not restart |
| Bluetooth output connected while playing | continues on it |
| Screen off ten minutes | still playing; the foreground notification shows "Playing <project>" on Android with a working Stop action |
| Another destination chosen while playing | the dialog; both answers |

## 10. Performance

1. `./gradlew -Ptembra.perf=true :androidApp:assemblePerf :perf-benchmarks:assemblePerf`.
2. `cd app/perf && uv run tracepulse run --device pixel6 --label 009-timeline --rounds 1 --no-publish --no-build --apk … --test-apk …` as a trial: the `timeline` journey completes, its sections appear, `audio.starvation` reads 0.
3. `uv run tracepulse profile generate --device pixel6`; commit both profile files;
   `profile verify`; `profile compare --journeys timeline` (evidence).
4. After merge: the labelled sessions (contracts/perf-instrumentation.md) on pixel6, the
   Pixel 7 Pro and iphone14, five rounds each; `sync`, `report --open`; the report is PR evidence.

## 11. Troubleshooting

- MP3 clip seeks audibly late on the Pixel: check the seek table is built at `openClipSource`
  (research R5); the fallback is the decoded cache for MP3 described there.
- `audio.starvation` > 0 during the journey: raise the fifo to 32 768 frames or the prime window
  to 4 s; check the reader thread's priority.
- Playhead visibly ahead of the sound on Bluetooth: `latency_ns` must come from the route
  (`refreshOutputLatency` after a route change).
- `BaselineProfileCoverageTest` fails: regenerate the profile after adding the coverage lines.
- The iOS frames family is dropped for `timeline`: the pinch must produce drawn frames inside
  the animation interval; lengthen the gesture.
