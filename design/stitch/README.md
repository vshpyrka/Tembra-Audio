# Stitch design export

Pulled from Google Stitch project **Tembra Audio DAW Design** on 2026-09-17.

- Project: https://stitch.withgoogle.com/projects/12040171611712589599
- Design system asset in Stitch: `assets/fb1657e091d24ba8a3e2aa5dee703ce3`, titled **Tembra Audio** (renamed from "Tembra Pro Audio" on 2026-09-17).

## Files

| File | What it is |
|------|------------|
| `DESIGN.md` | The design system verbatim from Stitch: token front matter (colors, typography, radii, spacing) plus the style guide prose. Source of truth for look and feel. |
| `theme.json` | The same tokens as machine-readable JSON, plus the hand-picked DAW colors named in the prose (surface levels, playhead, clip fills, pad wine tones, glow). Use this to generate the Compose theme. |
| `screens.json` | Manifest of every generated screen: Stitch screen ID, title, device, dimensions, download URLs. Used by the re-pull script below. |
| `screens/<screen>/<device>/index.html` | Full HTML + Tailwind source of each screen, as generated by Stitch. |
| `screens/<screen>/<device>/screenshot.jpg` | Full-resolution render of each screen. |

## Navigation model (derived from the screens)

- **Primary destinations:** Timeline, Tuner, Effects, Pads, Projects in the original concept screens. The app's shell, which the tuner and metronome screens mirror, has Timeline, Tuner, Metronome, Projects, Profile; Home was removed on 2026-10-17.
- **Icon-only (2026-10-17, owner's decision):** no navigation item shows a text label; the destination's name is the icon's accessibility label. Every screen with a bar or rail was re-uploaded that way (old instances hidden), concept screens keeping their own item sets. The bar and rail follow the app's Material 3 Expressive components:
  - **Phone (bottom bar, `ShortNavigationBar`):** 64px content height plus the system inset, `surface-container-lowest`, items spread evenly, 24px icons in `on-surface-variant`; the active icon sits on a 56 × 32 fully rounded `primary-container` pill in `on-primary-container`.
  - **Wider windows (rail, collapsed `WideNavigationRail`):** 96px wide on `surface-container-lowest`, running the full height; items stacked from 44px below its top, 56px each and 4px apart, 24px icons in `on-surface-variant`; the active item is a 56px `secondary-container` circle with an `on-secondary-container` icon. Material draws the collapsed rail's indicator as a circle when the item has no label; that is what the app shows (Pixel 6 Pro and Pixel Tablet captures), so the mocks draw a circle, not a 56 × 32 pill.
  - **Glyphs (2026-10-17 (2)):** Material Symbols Outlined for every item except Tuner and Metronome, which have no Material Symbol: Tuner is a hand-drawn tuning fork (two prongs joined by a U, a stem, one sound arc each side) and Metronome a hand-drawn pyramid metronome (body, scale plate, a rod leaving through a gap in the body's right edge), both on the 24 × 24 grid in 2-unit strokes with round joins and flat ends, coloured like the neighbouring glyphs. The app draws them as `ic_tuning_fork_24` / `ic_metronome_24`, written by `app/tools/make-nav-glyphs.py`; the mocks carry the same paths as inline SVG. The concept screens' Tuner item uses the fork too, their other glyphs stay; the tuner's preset picker keeps its music note.
- **Secondary:** Remote (collaboration / remote control) appears on the tablet rail and in the original mockups; Users and Comments appear only in the mockups.
- **Global chrome:** top bar with menu, product name / screen title, cloud-sync icon, help, share, avatar (2026-10-16: the app's shell shows no top bar, so the fourteen tuner and metronome screens (`instrument-tuner/tablet`, whose export held the timeline's markup, was rebuilt as a tablet Auto Listen tuner), and the seven exploration and variant screens that carried it (tuner landscape `-d`, by-ear `-c`, `-e`, `-g`; the three Metronome Compact variants), were re-uploaded without it: their content starts under the status bar and the rail runs from the top; the screens of later features keep theirs). Transport bar (volume, return-to-zero, rewind, play/pause, fast-forward, timecode, speed chip, metronome toggle) is present on every DAW screen, including Effects and Export.
- **Inconsistency to resolve in the spec:** the tablet timeline rail names the items "Tracks, Tuner, FX, Pads" (as accessibility labels since 2026-10-17) while every other concept screen uses "Timeline, Tuner, Effects, Pads, Projects". Treat the latter as canonical.

## Build notes

- **Fonts:** Space Grotesk (500/600/700) for headlines, labels, timecode; Inter (400/500/600) for body and parameter readouts. Both are Google Fonts under the SIL Open Font License, fine for an open-source app. Bundle them; do not fetch at runtime.
- **Tabular numerals** are mandatory on every live-updating number (timecode, Hz, dB, BPM, pad index). In Compose this is `FontFeatureSettings("tnum")`.
- **Icons:** every screen uses Material Symbols Outlined (about 110 distinct glyphs, see `grep material-symbols-outlined screens/*/*/index.html`). Material Symbols are Apache-2.0 and available in Compose via `androidx.compose.material.icons` or as a bundled variable font.
- **Colour tokens:** `theme.json → namedColors` is a Material 3 dark tonal palette seeded from primary `#a78bfa`, secondary `#f472b6`, tertiary `#8b5cf6`, neutral `#0f0f12`. It maps one-to-one onto Compose `darkColorScheme(...)`. `dawSemanticColors` are the extra hand-picked values the prose relies on (surface levels 0–4, playhead, clip fills, pad wine tones); model them as a custom `LocalDawColors` composition local rather than overloading the Material scheme.
- **Radii:** the design system's scale is 4 / 8 / 12 / 16 / 24 px + pill. Track lanes and panels 12–16px, clips and pads 8–12px, chips and transport buttons pill.
- **Spacing:** 4/8px base module, 12px gutter, 16px page margin, 44px minimum touch target.
- **Elevation:** no drop shadows. Depth comes from stepping surface levels and 1px `#2B2A34` seams. The only glow is `0 0 12px rgba(167,139,250,0.25)` on active clips and nodes.
- **Per-screen drift:** the Tailwind config embedded in each HTML file is not identical across screens. Six screens carry no config at all, and the drum-sequencer phone screen uses its own slightly different palette (`#121116` surfaces, `#ec4899` active pad) plus amber and cyan step colours that are not in the design system. When these conflict, `DESIGN.md` and `theme.json` win.
- **Metronome implementation:** feature 004 implements the three metronome screens (`metronome/phone`, `metronome/tablet`, `metronome/phone-landscape`) in `app/shared/ui` (`audio.tembra.ui.metronome`). The landscape screen's twenty off-token greys and roses are followed for layout only; each is mapped to the nearest token of the phone screen, and no new colour was added (`specs/004-metronome/research.md` R10).
- **Screenshot artefact:** Stitch renders uploaded screens on a 1280-wide canvas (2560 × 1600 or taller, PNG data despite the `.jpg` name), so the phone screens uploaded as HTML (the metronome and tuner phones, and since 2026-10-17 every concept phone screen) have a `screenshot.jpg` that stretches the 390-wide layout across a wide frame; the HTML is the phone layout. Passing `deviceType: MOBILE` with the upload does not change this (tried 2026-10-17). Headless Chrome clamps its window to 500 px wide, so render local checks at 500 × 844 and read the centred 420 px column.
- **Screenshot artefact:** `instrument-tuner/phone/screenshot.jpg` rendered with a serif fallback font and an overlapping title; the HTML is correct. Rely on the HTML for that screen.

## Re-pulling from Stitch

The Stitch MCP server is configured in Claude Code (`claude mcp get stitch`). To refresh after editing in Stitch:

1. Call `get_project` for `projects/12040171611712589599` and copy `designTheme.designMd` into `DESIGN.md` (keep the `name: Tembra Audio` line and the source comment). Keep the `### Sliders` component entry too if the pulled text lacks it (added 2026-10-06, feature 006). The project's own `designTheme` was never changed by that work; the design system asset `assets/fb1657e091d24ba8a3e2aa5dee703ce3` was, through the MCP's `update_design_system`, and that tool is not a plain write: it runs a Stitch session that re-derives the palette from the colours it is given and rewrites parts of the prose. The first call (with the token front matter in `designMd`) shifted `primary` to `#e8deff` and the outlines with it; a second call with the original seeds (`customColor` and the four overrides) and the prose alone put every named colour back (version 4, checked against the project's theme) and kept the Sliders entry, but the asset's prose now differs from this file in wording and in a few surface hex values. This file and `theme.json` stay the source of truth; do not copy the asset's prose over it, and pass only the seeds and the prose when the asset has to change again.
2. Call `list_screens` and update the URLs in `screens.json` if any screen was regenerated.
3. Run the download step (Python, no dependencies):

```bash
cd design/stitch && python3 - <<'EOF'
import json, os, urllib.request
for s in json.load(open('screens.json'))['screens']:
    d = os.path.join('screens', s['slug']); os.makedirs(d, exist_ok=True)
    for key, fn in (('html', 'index.html'), ('screenshot', 'screenshot.jpg')):
        url = s[key] + ('=s0' if key == 'screenshot' else '')
        req = urllib.request.Request(url, headers={'User-Agent': 'Mozilla/5.0'})
        open(os.path.join(d, fn), 'wb').write(urllib.request.urlopen(req, timeout=120).read())
EOF
```

The `=s0` suffix asks Google's image host for the original size; without it you get a 512px thumbnail.
